Detailed Description

The work a block does on its pipes (threads.md §6.8), placed so that most of it runs inside the tasks: each audio and event pipe of the table, and each private pipe, starts (zeroed or emptied for the block) just before the node that first uses it in the order runs, when that node writes it, and each audio pipe publishes its last samples just after the node that last writes it.

The audio thread does the rest, before and after every node. Built on the builder thread with the order's schedule; the audio thread and the workers only read it.

A start in a node is race-free: the node is the first in the order to use the pipe, and every later user follows it through the dependencies (threads.md §4.1.2), in every order the dependencies admit. Feedback pipes, whose reads follow no writer, start and end on the audio thread.

◆ touches

std::vector<std::uint8_t> primitives::pipeWork::touches

For each node, the work it does on pipes, as bits: one byte the runner reads for the many nodes that do none.

touchesPipes when it starts or publishes a table pipe or starts a private pipe without a target; touchesForwarding when it starts a private pipe with one (aPipe::hasTarget). A plan whose private pipes forward starts none of those (threads.md §4.2.5), so its runner skips a node with only the second bit without reading its pipes.

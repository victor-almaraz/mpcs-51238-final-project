Detailed Description

The nodes of an execution order grouped into tasks (threads.md §5): a thread runs a task's nodes in order, start to finish, once every task it waits for has finished.

Member Data Documentation

◆ criticalPath

double primitives::taskList::criticalPath = 0.0

The estimated critical path, in nanoseconds a block: the costliest path through the task graph by the tasks' costs.

No number of threads runs the tasks in less.

◆ parallel

bool primitives::taskList::parallel = false

True when the tasks run on the engine's threads: some level of the task graph holds two tasks, which can run at once, and the estimated saving at the engine's thread count (savingAt) reaches scheduleOptions::minimumParallelSaving.

The engine runs tasks that are not parallel on the audio thread alone, in nodeSchedule::serialOrder, waking no worker (threads.md §6.1.1).

◆ work

double primitives::taskList::work = 0.0

The estimated work of a block run as tasks, in nanoseconds a block: the sum of the tasks' costs.

A task costs its nodes' estimated costs and a fixed cost for each dependency of one of them on a node of another task, whose output its thread must read from another processor's cache (threads.md §6.1.1).

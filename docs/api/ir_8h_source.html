59/// Semantic checks (`interpreter.md` §12.3) of the graph's declarations,
60/// its nodes against the primitive tables, and its page layout against
61/// the page kinds; `checker::run` in validate.cpp lists them. Execution
62/// order (every reader of a pipe after all of its writers, except through
63/// feedback pipes) is checked only when every other check passes.
64std::vector<error> validate(const metadata::graphSpec& graph);
65
66/// Sorts the nodes of @p graph so every writer of a pipe precedes its
67/// readers, except through feedback pipes, and every writer of a buffer
68/// precedes its readers where that closes no cycle; ties keep the original
69/// order. When the graph has a cycle, leaves it unchanged and returns the
70/// original indices of the nodes on cycles, in order.
71std::vector<std::size_t> sortByDataFlow(metadata::graphSpec& graph);
72
73/// Likely audio hazards in a valid, sorted graph, for warnings: a loop
74/// through audio feedback pipes with a gain of 1 or more once around
75/// (estimated from static `gain`, `adsr` and `mix` levels per input
76/// position, along every path through inputs and parameters bound to
77/// audio pipes, including paths through other feedback pipes; parallel
78/// paths summed; when a node or parameter of unknown gain is on the loop,
79/// only an estimate above 1 warns), one warning per set of feedback pipes
80/// that reach each other; constant audio gains above +24 dB; constant
81/// frequencies above half of @p sampleRate; and a buffer written by more
82/// than one node.
83std::vector<error> hazards(const metadata::graphSpec& graph, double sampleRate);

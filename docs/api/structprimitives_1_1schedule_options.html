Detailed Description

How the builder makes the schedules of plans and crossfades (engineOptions::schedule).

The output is the same at every setting.

Member Data Documentation

◆ minimumParallelSaving

double primitives::scheduleOptions::minimumParallelSaving = defaultMinimumParallelSaving

The least estimated saving a block, in nanoseconds, not negative, for which tasks that can run at once run in parallel on threads threads (taskList::savingAt, taskList::parallel); with less, the block runs in order on the audio thread.

At 0 every schedule whose tasks can run at once is parallel, which tests use to run every plan on the pool; an infinite one makes every schedule serial.

◆ minimumTaskCost

double primitives::scheduleOptions::minimumTaskCost = defaultMinimumTaskCost

The least estimated cost of a task, in nanoseconds a block, not negative (threads.md §5.2): the builder joins chains of nodes that cannot reach each other into one task until it holds this much.

At 0 every chain is a task of its own, the finest partition, which tests use so that independent nodes run on different threads.

◆ shuffleSeed

std::optional<std::uint64_t> primitives::scheduleOptions::shuffleSeed = std::nullopt

For testing that the dependencies capture every conflict (threads.md §5.5, §9.1): when set, a block whose nodes one thread runs alone (one thread, or tasks that are not parallel or do not fit the pool) runs them in a random order that keeps every dependency (nodeSchedule::serialOrder), drawn from this seed alone once for each plan and each crossfade, instead of plan order.

A node that touches shared state it does not declare then renders differently.

◆ threads

int primitives::scheduleOptions::threads = 1

The threads that run a block, the audio thread included: the engine sets it to engineOptions::threads.

At 1 no schedule is parallel (taskList::parallel).
